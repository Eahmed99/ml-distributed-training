## 1. Problem formulation

The goal is to evaluate the performance and correctness of synchronous data-parallel ResNet-18 training on CIFAR-10, contrasting a CPU baseline with a two-GPU system and (ideally) a one-GPU scaling baseline. CIFAR-10 contains 50,000 labeled training examples and 10,000 labeled test examples in ten classes. Its small image size allows meaningful batch processing while retaining the compute-intensive convolution/backpropagation workload.

**Performance expectations to validate, not assumed results:** two T4 GPUs should process training images faster than four CPU threads; two GPUs may be faster than one T4, but scaling will be below ideal linear efficiency because of communication and system overhead. Accuracy differences should be measured rather than assumed.

## 2. Design and justification

**Model:** randomly initialized ResNet-18 with 3x3 stride-one input convolution, removed initial max-pooling, ten-class classification head. This adapts the architecture to 32x32 images.

**Parallelism:** synchronous data parallelism with one full model replica and one Python worker process per GPU. `DistributedSampler` partitions indices, with a global batch of 128 (64 per GPU for two GPUs).

**Communication:** PyTorch DistributedDataParallel with NCCL gradient All-Reduce during backward passes; gradients are synchronized before local SGD optimizer steps. The design avoids asynchronous stale gradients and custom gradient transport.

**Framework and execution:** PyTorch/TorchVision. A single host with two CUDA GPUs is sufficient; CPU baseline and optionally a one-GPU reference use the same model/training loop.

### Data and synchronization diagram

```text
                 CIFAR-10 train (50,000)
                            |
             DistributedSampler(seed, epoch)
                       /           \
                  Rank 0            Rank 1
                 25,000             25,000
                    |                  |
              batches of 64       batches of 64
                    |                  |
              ResNet-18 GPU0      ResNet-18 GPU1
                    |                  |
              forward/backward    forward/backward
                       \           /
                    NCCL All-Reduce
                            |
                synchronized gradients
                       /           \
                 SGD GPU0          SGD GPU1
```

Each rank holds a full model replica; layers are not partitioned across GPUs. Only rank 0 evaluates all 10,000 test images and writes results/checkpoints.

## 5. Deviation analysis

After collecting evidence, discuss:

- Why observed speedup deviates from ideal: gradient All-Reduce, synchronization, DataLoader overhead, CPU/GPU capability differences, GPU occupancy and scheduling.
- Why throughput varies by epoch: startup/warmup, data caching, runtime variability and resource contention.
- Why accuracy could differ: SGD numerical differences, dataset shuffle ordering, different BatchNorm local statistics, and random seed.
- Ways to improve: tune worker count and DataLoader prefetching, profile communication overlap, consider mixed precision only as a **separate** experiment, and add repeated trials.

Never use heterogeneous CPU-to-GPU acceleration as a measure of two-GPU parallel efficiency.
